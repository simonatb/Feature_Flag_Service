# Feature flag service

## Technology stack
| Layer   | Technologies                              | 
|---------|-------------------------------------------|
| Backend | Java 25, Spring Boot 4.1, Spring Data JPA |
| Database   | H2                                        | 
 | Tools | Maven, Lombok                             |

## Structure 

### Entity
Contains the Feature flag entity:

| Field | Type | Notes |
|---|---|---|
| `id` | generated | unique identifier |
| `name` | string | unique, e.g. `new-checkout-flow` |
| `description` | string | optional |
| `enabled` | boolean | |
| `createdAt` / `updatedAt` | timestamp | maintained by the service |

### DTO
Contains three dtos:
- CreateFeatureFlagRequest(String name, String description, boolean enabled)
- UpdateFeatureFlagRequest(Boolean enabled, String description)
- FeatureFlagEvaluationResponse(String name, boolean enabled)

**Haven't implemented FeatureFlagResponse dto because it would be identical to the entity (can be added when the project gets bigger)**

### Mapper 
Decided to manually map my dtos because I had troubles in the past debugging dependency versions for MapStruct

### Exception
Contains two custom RuntimeExceptions:
- DuplicateFeatureFlagNamesException
- FeatureFlagNotFoundException

And a global exception handler + ErrorResponse record

### Repository
Custom interface that abstracts the storage mechanism (FeatureFlagRepository). 
The current implementation uses Spring Data JPA with an H2 file-based database. 
Swapping to a different database will only require an implementation of the interface - no changes to the service layer.

### Service
Contains the business logic:
- Create feature flag
- Get all feature flag
- Get a feature flag by id
- Delete a feature flag
- Update a feature flag
- Evaluate a feature flag

### Controller 
Handles the HTTP concerns only

## Testing
Implemented tests for the controller and service class only. (No need to test getters, setters, dtos)

Wrote tests for the create, delete and update methods.

## Docker
Dockerfile and compose.yaml files generated by using 

```bash
docker init
```
**Added volume so when the container is stopped and deleted the flags are not lost**
## Running the application

```bash
docker compose up --build
```
